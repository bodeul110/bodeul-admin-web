# 개발 의존성 PR 정리

## 판단 기준

- 작업 목적: 누적된 봇 PR을 최신 개발 브랜치 기준으로 정리하고 React 버전 불일치로 실패한 테스트를 복구한다.
- 선택한 방식: React와 React DOM을 같은 버전으로 맞추고 승인된 변경만 하나의 개발용 lockfile에서 검증한다.
- 대안: 각 PR을 개별 병합하거나 운영 `master`에 직접 반영하는 방식을 검토했다.
- 선택 이유: 현재 MVP에서는 의존성 조합을 실제 개발 코드로 확인하고, 운영 변경은 별도 출시로 남기는 편이 안전하다.
- 리스크: 합성 설정의 빌드·회귀 검사는 실제 운영 로그인·결제·DB 동작 검증을 대신하지 않는다.

#107의 sharp 0.35.5와 플랫폼별 바이너리는 이미 개발 브랜치에 반영되어 있어 중복 변경하지 않는다. Node 25 타입 전환(#89), Firebase 13 전환(#100)은 제외한다. Node 22 검증 기준, 사용자 기능, 인가, API·DB 계약, 환경변수와 배포 설정은 유지한다.

## 검증

- Node 22.23.4에서 `npm ci`, 서버 계약 테스트 200건, lint 통과.
- 실제 Firebase에 연결하지 않는 CI 합성 설정으로 Next.js 빌드와 Vite rollback 빌드 통과.
- `check-built-admin-runtime.mjs`의 인증 경계 27건 통과. 정상 로그인·MFA·App Check와 실제 DB 쓰기는 이 검사의 범위가 아니다.
- React와 React DOM의 실제 lockfile 버전이 모두 19.3.1인지 확인했고, 기존 SSR·클라이언트 진입점 회귀 테스트를 통과했다.
- 오래된 Next.js PR에서 가져온 중복 sharp 하위 항목은 제거하고 개발 브랜치에 있던 동일 버전 바이너리를 재사용한다. 정리 후 `npm ci`와 테스트·빌드를 다시 통과시켰다.
- `master` 변경과 운영 배포는 실행하지 않는다. GitHub CI와 Vercel Preview 통과 후에만 `dev`로 병합한다.
