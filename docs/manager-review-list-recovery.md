# 개발 관리자 심사 목록 복구

## 판단

- 작업 목적: 개발 관리자 로그인 후 심사 목록에서 발생하는 서버 인증 오류를 해결하고, 조회 실패를 대상 0명으로 표시하지 않는다.
- 확인한 원인: 2026-10-29 Vercel Preview의 `/admin/manager-reviews`에서 Google 기본 자격 증명을 찾지 못했다. 로그인용 ID token 서명 검증과 PostgreSQL 예약 조회는 성공했으나, Firestore 조회에 사용할 서버 인증은 설정되지 않았다.
- 선택한 방식: 개발 Preview 목록 GET은 전용 Vercel OIDC/WIF 읽기 계정을 사용한다. 기존 인증 경로의 누락은 Firestore ADC 탐색 전에 구분된 오류로 반환한다. 화면은 조회 중·실패·성공을 구분하고 실패 시 재시도를 제공한다. 심사 목록 오류는 대시보드와 매니저 승인 화면에만 표시한다.
- 대안: 빈 목록 반환이나 오류 숨김은 실제 미조회 상태를 정상으로 오인하게 하므로 사용하지 않는다. 운영 자격 증명 복사와 광범위한 서비스 계정 키 재사용도 제외한다.
- 선택 이유: 현재 MVP에서 예약 조회와 심사 목록은 별도 데이터 경로이므로, 심사 장애가 정상적인 예약 시연을 가리지 않게 하되 실제 장애는 해당 화면에 남겨야 한다.
- 리스크: 이 방어 코드만으로 Firestore 연결이 복구되지는 않는다. 개발 서버 인증과 최소 읽기 권한을 별도로 설정하고 실제 Preview에서 검증해야 한다. 목록 조회 성공은 서류 열람·승인·반려·운영 업무 활성화를 뜻하지 않는다.

## 검증과 적용

코드 검증, 개발 인증 설정, Preview 배포와 실제 조회 확인을 구분해 기록한다. 운영 환경과 기존 계정의 비밀번호·권한은 변경하지 않는다.

- 구현: 서버 인증 누락 오류와 실패 감사, 민감한 내부 오류 비노출, 로컬 ADC 경로 보존, 목록 상태·재시도 표시.
- 인증 연결: 승인받은 개발 Preview 전용 OIDC/WIF 읽기 역할·연결과 Preview/dev 환경변수를 설정했다. 설정용 임시 관리 권한은 즉시 회수했다. 단위 테스트 186건, lint, Next.js·Vite 빌드와 빌드된 서버의 인증 경계 18건을 통과했다. 자세한 대상과 제한은 [전용 reader 운영 기준](manager-list-dev-reader.md)을 따른다.
- 실제 배포: 2026-10-29 [PR #85](https://github.com/bodeul110/bodeul-admin-web/pull/85)의 CI·CodeQL·Vercel 통과 후 `dev`에 반영한 `8f51497`을 확인했다. 관리자 인증과 심사 목록은 HTTP 200이며 목록 3명, 대시보드의 대기·검토·승인 각 1명을 표시했다. 기존 가상 예약과 40,000원 결제 원장·생성·취소 이력 조회도 HTTP 200이다.
- 오류 회귀: 브라우저 한 탭에서만 목록 GET을 503으로 모의 처리했다. 미조회 수치는 `-`로 표시하고 재시도를 제공했으며 예약 검색 메뉴에는 이 오류가 표시되지 않았다. 모의 응답을 제거한 뒤 재시도로 실제 목록을 다시 불러왔다. 서버 설정과 데이터는 이 테스트에서 변경하지 않았다.
- 실기기: 사용자 요청에 따라 이번 검증에서 제외.
- 시연 범위: 개발 관리자 대시보드·마스킹된 매니저 심사 목록·기존 가상 예약·결제 원장 조회. 환자 완료 리포트는 별도 Core API 응답까지만 확인했으며 실기기 화면 검증과 구분한다. 신규 예약·매칭·심사 승인·서류 열람·결제 변경과 DB seed는 별도 실행·검증 전까지 성공으로 기록하지 않는다.

근거: [Firebase Admin 서버 설정](https://firebase.google.com/docs/admin/setup), [Vercel의 Google Cloud OIDC 연결](https://vercel.com/docs/oidc/gcp).
